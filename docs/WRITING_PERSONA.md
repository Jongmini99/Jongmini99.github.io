# 문체 페르소나 — "만들어 보고 검증하는 기획자" 허종민

포트폴리오 PDF(`GAME DESIGN PORTFOLIO 2020–2026`, 27쪽)의 문장을 분석해 정리한 글쓰기 기준이다.
사이트 콘텐츠(`content/`), 컴포넌트의 UI 고정 문구, 관리자(CMS)에서 새로 쓰는 글은 이 기준을 따른다.
사실 확인 원칙(CLAUDE.md §2.2)이 문체보다 우선한다. 문장을 다듬더라도 수치·경력·결과를 바꾸거나 새로 만들지 않는다.

---

## 1. 화자

| 항목 | 내용 |
| --- | --- |
| 정체성 | 시스템 게임 기획자 신입. 기획서를 쓰고, 엔진(Unity·MSW)으로 직접 만들어 보고, 플레이로 검증한다. |
| 한 줄 소개 | **만들어 보고 검증하는 기획자** (PDF 표지·About Me 헤드라인) |
| 태도 | 과장 없이 담백하다. 잘된 점과 막혔던 점을 같은 무게로 쓴다. 판단의 근거(테스트·지표·피드백)를 항상 함께 적는다. |
| 독자 | 채용 담당자·면접관. 바쁘게 훑어보므로 결론(무엇이 나아졌는가)을 먼저 보여 준다. |

## 2. 문체 원칙

1. **합쇼체 평서문**을 쓴다. `~합니다 / ~했습니다 / ~입니다`. 해요체·반말은 쓰지 않는다. (예외: 인용한 테스터 의견은 원문 그대로)
2. **주어 '저는'을 생략**한다. 문맥상 화자가 분명하다. AI·동료와 역할을 나눌 때만 `본인`, `허종민`처럼 명시한다.
3. **수식어보다 숫자**를 쓴다. `3개월`, `11개 → 7개`, `테스트 5명`, `4번의 개선`, `69쪽`처럼 구체적인 값을 넣는다.
4. **과장·자기평가를 하지 않는다.** `압도적`, `완벽한`, `극대화`, `혁신적`, `최고의 인재`, `~할 수 있는 역량을 갖춘 인재` 같은 표현은 쓰지 않는다. 결과는 사실로 보여 준다.
5. **정직하게 회고한다.** 실패와 정체도 원인과 함께 쓴다. (예: "팀 역량 대비 큰 목표로 인해 방향성을 정하지 못하고 3개월간 방황했습니다.")
6. **비유는 아껴 쓴다.** 핵심을 바로 전달하는 구어 비유는 한 섹션에 최대 한 번만 쓴다. (예: "백견이 불여일행", "철권을 하는 듯한 경험")

## 3. 문장 흐름: 문제 해결 서사

본문(섹션 소개 문단)은 2~3문장으로, 아래 순서를 따른다.

```
[상황] ~를 진행했습니다.
→ [문제] 의도와 달리 ~했습니다. / ~라는 피드백을 받았습니다.
→ [조치] 이를 개선하기 위해 ~를 추가해 ~하도록 유도했습니다.
→ [결과] ~할 수 있었습니다. / ~를 확인했습니다.
```

자주 쓰는 연결어: `의도와 달리`, `이를 개선하기 위해`, `따라서`, `이를 통해`, `그 결과`, `또한`

> 예) 전투 시스템 기반의 프로토타입으로 내부 테스트를 진행했습니다. 의도와 달리 인간 플레이어는 좀비를 피해 숨는 데 집중했고, "전투보다 숨바꼭질 같다"는 피드백을 받았습니다. 이를 개선하기 위해 상자와 레벨업 시스템을 추가해 맵 이동을 유도했고, 전투 상황 발생 빈도를 높일 수 있었습니다.

## 4. 형식별 규칙

| 형식 | 규칙 | 예시 |
| --- | --- | --- |
| **섹션 헤드라인** | 결과가 보이는 한 줄. `A로 B 증가/제공/확정` 명사형, 또는 `~했습니다` 서술형. 목차에 들어가므로 25자 안팎. | `상자·레벨업 시스템으로 전투 발생 빈도 증가` / `3개월 막힌 방향을 최소 프로토타입으로 검증` |
| **불릿** | 한 줄, **명사형 종결**(`~ 증가`, `~ 정리`, `~ 확인`, `~ 부족`). 상태를 말할 때만 `~음/~함` 허용. 변화는 `→`로 표기. | `관리 난이도 의견을 수용해 테이블 11개 → 7개로 효율화` |
| **카드 3단 요약** | 문제·해결·결과 각 한 줄, 명사형 종결. 결과에는 수치나 외부 검증(수상·출시)을 넣는다. | `숨는 플레이 → 돌아다니는 플레이로 전환되어 전투 발생 빈도 증가` |
| **라벨** | 짧은 명사. 단계 구분은 `문제 / 판단 / 검증`, `기획 의도`, `문서 디테일`. | `[문제] 모호한 방향성으로 3개월 정체` |
| **소개 문단** | 2~3문장 합쇼체. 첫 문장은 무엇인지(정의), 다음 문장은 맡은 일. | `~는 ~를 메인으로 하는 멀티 플레이 PvP 게임입니다.` |
| **역할 분담** | 사람과 AI의 몫을 나눠 쓴다. 기획·판단·검수는 본인, 구현·제안은 AI. | `기획·검증: 허종민 / AI 사용: Claude Code, ChatGPT` |

## 5. 표기 규칙

- 나열은 가운뎃점 `·` (예: `기획서 작성·일정 관리·QA·고객사 응대`), 대안·묶음은 슬래시 `/`.
- 게임 용어는 PDF 표기를 따른다: `인 게임`, `아웃 게임`, `플레이 타임`, `덱 빌딩`, `레벨 디자인`, `데이터 테이블`, `프로토타입`.
- 고유명사: `Unity`, `MSW(메이플스토리 월드)`, `Steam`, `Claude Code`, `ChatGPT`, `Python`.
- 숫자와 단위는 붙여 쓴다: `3개월`, `5명`, `69쪽`, `4.99 USD`. 버전은 `v0 → v1.3`.
- 외부 자료는 출처를 남긴다: `이미지 출처: 팡이요 유튜브`. 주의가 필요한 링크는 안내한다: `음량 주의`.

## 6. 쓰지 않는 표현

| 피하기 | 대신 |
| --- | --- |
| 압도적인 게임 이해도 | 최상위권 플레이 경험과 높은 게임 이해도 |
| ~를 완벽하게 도식화 | ~를 플로우차트로 도식화 |
| 전환율 극대화, 혁신적인 시스템 | (수치나 결과로 대체) |
| 저는 ~를 맡아 | ~를 맡아 |
| ~했어요, ~해요 | ~했습니다, ~합니다 |
| 근거 없는 백분율·순위 (예: 상위 0.05%) | PDF에 있는 지표만 (예: 마스터 550pt) |
